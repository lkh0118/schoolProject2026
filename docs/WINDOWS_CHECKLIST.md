# Windows 11 수동 확인 절차

**아래는 수행할 절차이며 이번 Linux 세션에서 통과했다고 보고하는 항목이 아닙니다.** Windows 결과는 CPU/GPU/RAM/드라이버/디스플레이 배율과 함께 기록하세요.

1. Python 3.12 x64와 FFmpeg/ffprobe를 준비하고 `scripts/setup-windows.ps1` 실행. `doctor`의 경로·버전과 pytest 출력 보관. 필요 시 Microsoft의 공식 Visual C++ 런타임 설치 안내에 따라 CTranslate2 런타임 의존성 해결.
2. `scripts/run-windows.ps1` 실행. 한국어 글꼴, 100/150/200% 배율, 작은 창·다중 모니터 이동에서 잘림 확인. 이 단계는 앱 UI 검증이며 다중 모니터 **녹화** 지원 확인이 아님.
3. 본인이 제공할 수 있는 2~5분 MP4와 MKV를 각각 가져오기. 가능하면 한국어 아군 음성, 스테레오 게임 소리, 마이크가 별도 트랙인 자료 포함. 가져오기 전 원본 해시와 가져온 사본 비교.
4. 재생·일시정지·탐색·사건 클릭·근거 링크 이동·자막 확인. 실제 출력 장치로 소리를 듣고 음성 트랙 변경을 확인. Qt FFmpeg가 설치된 코덱을 재생할 수 있는지 확인. 재생 실패 시 원본은 남아야 함.
5. 로컬 다국어 faster-whisper 모델 지정 후 처음 분석할 음성 트랙 선택. 첫 전사 실행, 한국어 주요 발화 수동 대조, 잡음/무음 구간의 허위 전사와 누락 기록. 이름·방향·부정 표현을 정확히 알아들었다고 가정하지 않기.
6. 전사 내용·시각 수정, 확인 체크 변경, 이전 발화 정정 지정. 재분석 전 오래된 보고서가 보이지 않는지, 이후 정정이 이전 판단에 섞이지 않는지 확인.
7. 수동 사건 추가 후 클릭 재생, 전제·이점·위험이 있는 조건부 비교와 판단 보류 표시 확인. 실제 적·교전을 자동 판정한 것으로 해석하지 않기.
8. 분석 중 다음 영상 가져오기. 같은 경기의 중복 분석 버튼, 취소, 앱 닫기·재시작, 존재하지 않는 모델 경로를 시험. 원본·이전 보고서가 보존되고 중단/실패/재시도 상태가 드러나는지 확인.
9. 저장 한도를 낮춰 새 가져오기 실패 유도. 실제 디스크를 가득 채우는 위험한 시험 대신 테스트용 작은 볼륨에서 확인. 기존 원본·DB가 유지돼야 함.
10. 감도 프로필 두 개와 서로 다른 배율을 등록. 30fps 또는 반동·가림 표본이 제외되고, 자료가 부족하면 수치 추천이 나오지 않는지 확인.
11. 클립 저장 시 아군 음성 포함 확인 표시, 원본 범위 내 클립, 오디오 트랙 유지 확인. 외부로 내보낸 사본은 경기 삭제와 별개로 직접 관리.
12. 테스트 경기 삭제 후 앱 내부 원본·전사·보고서·감도 표본·의견이 지워지는지 확인. 사용자가 가져오기 전에 가지고 있던 원본은 유지돼야 함.

WASAPI 장치 변경/분리, 실제 게임 캡처, 하드웨어 인코더, 안티치트 호환성, 녹화 FPS·게임 FPS 저하는 **2단계 구현 후 별도 확인 대상**입니다.
